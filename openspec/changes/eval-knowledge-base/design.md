## Context

本 change 建立在 `platform-foundation` 之上（Next.js 站点骨架、SQLite/Drizzle 数据层、发布链路均已就位）。需要交付 totalk.ai 的内容主力：评测知识库词条，并用「AI 生成种子 + 人工审核」解决空站冷启动。

约束条件：

- 内容由 AI 批量生成，准确性必须靠流程而非信任来保证
- 平台为内容站，词条页是 SEO 主战场
- 单机部署，不引入额外服务（如外部搜索引擎）
- 词条第 一期就要能被后续评测文章引用互链

## Goals / Non-Goals

**Goals:**

- 交付完整的评测词条能力：模型、渲染、分类标签、搜索、SEO
- 建立「AI 生成草稿 → 人工审核 → 发布」的内容闭环
- 保证未审核内容在任何路径下都不会对前台可见
- 让词条成为后续评测文章可引用的知识节点

**Non-Goals:**

- 助手档案、评分卡、评测文章（属于 `assistant-profiles-and-reviews`）
- 社区讨论、评论、用户投稿
- 词条版本历史与多人协作编辑
- 全文检索的分词精度优化（先保证可用）

## Decisions

### D1. 正文存储：MDX 存数据库，而非文件系统

词条正文以 MDX 文本存入 `wiki_entries.content`（TEXT 字段）。

理由：审核态、草稿态、回滚与统一查询都依赖数据库事务与状态字段；文件系统方案下「草稿不可见」与「审核通过后发布」都要额外机制，且不利于 sitemap 与搜索的统一构建。

备选：Git 仓库 Markdown + 构建时静态生成——SEO 最好且部署简单，但 AI 生成内容的审核流转难以承载，排除。

### D2. MDX 渲染：服务端 RSC 渲染 + 组件白名单

使用 RSC 方式在服务端编译 MDX，只允许白名单组件（标题、列表、代码块、引用、表格、内部词条链接），不启用任意 JSX 执行。渲染前对 AI 生成的原始内容做消毒处理。

理由：正文由 AI 生成，等同于不可信输入，必须防注入。

备选：预编译为 HTML 再存库——更安全但失去组件能力与互链灵活性，作为降级方案保留。

### D3. 站内搜索：SQLite FTS5 + bigram 切分

建立 FTS5 虚拟表，中文文本在写入时按 bigram（二字组）切分索引。

理由：单机不引入外部服务；bigram 对中文短查询效果可接受，且无需引入分词依赖（如 nodejieba）。

备选：Meilisearch/Elasticsearch——检索质量更高，但单机部署资源占用与运维成本不匹配。

### D4. SEO：动态 sitemap + robots + JSON-LD + 动态 OG 图

- `app/sitemap.ts` 从数据库读取全部已发布内容（词条 + 后续类型）生成
- `app/robots.ts` 屏蔽 `/admin`
- 词条页注入 JSON-LD（以 `DefinedTerm` / `Article` 描述）
- OG 图用 ImageResponse 按标题动态生成

理由：内容站的流量主要来自搜索，SEO 必须在第一版就内建而非后补。

### D5. 分类与标签：单值分类 + 多对多标签

分类为单值枚举（方法论 / 指标 / 术语 / 工具 / 案例），标签为多对多关联。分类决定导航与聚合页，标签决定横向关联。

理由：分类用于结构化导航（必须唯一），标签用于网状关联（必须多值），二者职责不同。

### D6. 审核后台：`/admin` 统一队列

`/admin` 展示全部内容类型（本 change 只有词条）的草稿与待审列表，支持预览、通过、打回并填写理由。登录复用地基的口令 + signed cookie 机制。

### D7. 草稿不可见：查询层强制过滤 + 路由层 404

所有前台数据访问统一经过 `publishedOnly()`；非 published 内容在路由层直接 `notFound()`。

理由：单点过滤容易在新增页面时被遗漏，因此查询层与路由层双重设防。

### D8. 种子生成脚本：`scripts/seed-wiki.mjs`

脚本按词条大纲调用 AI 生成内容，输出为 `draft` 状态；生成时强制要求每条事实性内容附带来源字段，无来源的内容在审核界面被显著标记。

### D9. 来源与数据日期为必填约束

词条模型包含 `sources`（JSON 数组）与 `data_date`。审核规则：涉及具体数字、排名、价格的内容，来源不可为空。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| AI 生成内容出现幻觉（指标定义、数字错误） | 草稿态 + 人工审核（D6）；事实性内容强制来源（D9）；无来源显著标记 |
| MDX 内容注入恶意脚本 | 服务端渲染 + 组件白名单 + 内容消毒（D2） |
| FTS5 中文检索效果有限 | bigram 切分；词条量初期较小（百级），必要时降级为 LIKE 查询 |
| OG 动态图生成增加服务端成本 | 结果按 slug 缓存，避免重复渲染 |
| 词条分类体系与后续内容不匹配 | 分类枚举集中在单一定义处，扩展成本低 |
| 审核成为瓶颈导致内容堆积 | 后台按状态筛选与批量操作，MVP 阶段内容量可控 |

## Migration Plan

无历史数据迁移。执行顺序：

1. 新增 `wiki_entries`、`tags`、`wiki_entry_tags` 表与迁移
2. 建立 FTS5 虚拟表，并对存量词条回填索引（本 change 无存量）
3. 上线 `/wiki`、`/wiki/[slug]`、`/admin`、`/api/search`
4. 运行 `scripts/seed-wiki.mjs` 生成草稿
5. 人工审核通过后发布，验证 sitemap 与前台可见性

回滚：本 change 全部为新增表与新增路由，回滚只需移除路由与删除新增表，不影响地基。
